# v0.1.0 — 2026-10-31

首个可工作的 ESP32-S3 手持 Remote ID 扫描器。

## 硬件

- 主控：ESP32-S3-DevKitC-1 公版，双 USB-C、BOOT/RST、板载天线，16MB flash，无 PSRAM
- 屏幕：ST7735S 1.8" 128x160 SPI，8 针，3.3V
- 按键：4 个独立轻触按键，K1~K4 接 GPIO4/5/6/14，另一端接 GND
- 屏幕接线：SCK=GPIO12、MOSI=GPIO11、CS=GPIO10、DC=GPIO9、RST=GPIO8、BLK 先接 3V3（可改 GPIO7）
- 屏幕偏移：本机面板使用 `LCD_OFFSET_X=4, LCD_OFFSET_Y=0`
- 供电：USB 5V；屏幕和逻辑都用 3.3V

## 功能

### Remote ID 接收

- **WiFi Beacon**：2.4GHz ch6 promiscuous，解析厂商 IE
  - OUI `FA:0B:BC`（ASD-STAN）和旧 OUI `90:3A:E6`
  - OUI type `0x0D`，后接 message counter + OpenDroneID message pack
- **WiFi NAN**：抓 NAN Action 帧，调用 OpenDroneID 的 NAN 解析函数
- **BLE**：被动扫描 Service Data UUID `0xFFFA`，app code `0x0D`
  - 遍历 AD structure，不假设 Service Data 一定在第一个
  - 支持单条 25 字节消息和 message pack
- **纯被动**：不连接 WiFi、不主动扫描、不发射；BLE `setActiveScan(false)`，连 `SCAN_REQ` 都不发
- 目标表最多 16 架，30 秒无更新自动移除

### 显示与交互

- LovyanGFX 驱动 ST7735S，逻辑分辨率 160x128（rotation 1）
- 160x128、16 位色离屏 sprite 双缓冲，整屏 `pushSprite`，消除刷新闪烁
- 列表页：ID、RSSI、经纬度、目标数量、`NF-xx` 噪声底
- 详情页三页：
  - P1：ID、LAT/LON、ALT/HGT、SPD/HDG、SRC/RSSI
  - P2：OPERATOR ID、OP LAT/LON、AGE、MAC、SRC/RSSI
  - P3：RF STATUS，CH/PPS/NOISE/RSSI/PKT/MGMT
- K1/K2：切换目标
- K3 短按：列表进详情 / 详情翻页
- K3 长按约 0.7 秒：返回列表
- K4：可用时直接返回；测试模块的 K4 不稳定，长按 K3 是备用方案

### RF SCAN

- 列表页长按 K3 进入，自动每 1 秒轮询 ch1/6/11
- 显示每信道 PPS、NOISE、RSSI，当前信道高亮
- K3 短按手动换信道，长按退出并恢复 ch6
- 进入 RF SCAN 时 WiFi RID 暂停（BLE 继续），退出后恢复
- 噪声底来自 `rx_ctrl.noise_floor`，是收包时的 PHY 估计，不是独立频谱仪
- 无包时 NOISE 显示 `--`，PPS 为 0

### 颜色与 `*` 标记

- 交通灯配色：
  - RSSI：绿 ≥ -60、黄 -80~-60、红 < -80 dBm
  - 噪声底：绿 ≤ -95、黄 -95~-85、红 > -85 dBm
- `*` 标记：
  - RSSI ≥ -50 dBm（能量强）
  - 噪声底 > -85 dBm（干扰大）
  - PPS ≥ 100（空口忙）

### 串口命令

- `s`：目标数量、剩余堆
- `w`：WiFi/RF 统计，包括每信道 PPS/噪声/RSSI
- `r`：切换 RF SCAN
- `d` / `c`：仅 `esp32s3-demo` 环境可用，本地注入/清空假目标，不涉及射频

## 构建环境

- PlatformIO + Arduino ESP32 core 2.0.17（`espressif32@6.9.0`）
- LovyanGFX 1.2.x
- OpenDroneID 解析文件来自 opendroneid-core-c / Sky-Spy，Apache-2.0
- 本仓库不提供预编译二进制，需自行用 PlatformIO 编译烧录
- 环境：
  - `esp32s3`：正式扫描器
  - `esp32s3-test`：屏幕 + 按键硬件测试
  - `esp32s3-align`：显示偏移校准
  - `esp32s3-demo`：本地假目标，用于 UI/按键测试，不发射

## 本次修复的关键问题

1. **扫描器没有调用 `buttonsInit()`**
   - 现象：K3 无反应，按键引脚浮空/被当作一直按住
   - 修复：`scannerSetup()` 中初始化按键并开启内部上拉
2. **BLE + WiFi 共存时 abort**
   - 现象：WiFi 先启动并设置 `WIFI_PS_NONE`，再启用 BT 时在 `coex_core_enable` / `pm_set_sleep_type` abort
   - 修复：先启动 BLE，再启动 WiFi；WiFi 使用 `WIFI_PS_MIN_MODEM`
3. **屏幕上下裁切**
   - 现象：顶部多 2 像素、底部文字被切
   - 修复：用 `esp32s3-align` 校准为 `LCD_OFFSET_X=4, LCD_OFFSET_Y=0`
4. **整屏刷新闪烁**
   - 修复：离屏 sprite 双缓冲
5. **K4 不稳定**
   - 处理：保留 K4 返回，同时加长按 K3 返回

## 验证结果

- WiFi Beacon 链路已用受控 ESP8266 测试源验证：
  - 测试源发送 0 dBm、30 帧、200ms 间隔的 Beacon
  - 串口出现 `[WiFi] ... id=TEST-8266-0001`
  - 统计 `vendor=2 odid=2`
  - S3 屏幕出现 `TEST-8266-0001`，RSSI 约 -56 ~ -61 dBm
- RF SCAN 实测能显示 ch1/6/11 的 PPS、NOISE、RSSI
- 屏幕、按键、三页详情、长按返回、双缓冲均已实机验证

## 已知限制

- **BLE RID 还没有用真实 BLE 广播源验证**；代码路径已实现并被动运行
- WiFi NAN 只抓 Action 帧，未验证完整 NAN 源
- ESP32-S3 只有 2.4GHz WiFi，收不到 5GHz WiFi RID，也收不到 5.8G 图传
- WiFi + BLE 共存时 WiFi 必须开 modem sleep，短脉冲可能漏帧；测试源需要连续多发才能稳定抓到
- `noise_floor` 是随包上报的估计值，不是真正的频谱/噪声计
- 没有广播 Remote ID 的无人机不会出现

## 升级注意

- 屏幕偏移因面板批次不同可能不同，换屏后先用 `esp32s3-align` 校准
- 如果 K4 不可用，长按 K3 返回
- 换 ESP32-S3 板子时检查 `include/config.h` 的引脚，避开 strapping/USB/flash/PSRAM 引脚
